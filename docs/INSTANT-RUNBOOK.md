# RAVIX Speech instant runbook — observed lessons

1. Scan the selected tab before editing. A generic chat textarea or Run control is not the speech editor. If needed use local bridge `open_speech`; wait for the speech landing page and open Create new dialog. Detect a welcome/terms dialog and act only with the user's specific authorization. Preserve existing drafts and output.

For an authorized setup, when the unique Create new dialog button appears on the verified speech landing page, click it once immediately; wait for the actual speech editor rather than a fixed post-click delay. A newly created tab is checked for readiness instead of sleeping a fixed seven seconds. If the page is wrong, blocked by a welcome dialog, controls are ambiguous or the editor does not appear, stop and inspect; do not click sample cards or repeatedly click. The `setup_and_run` timing includes `jobToCreateClickMs` when it opened the landing page; this measures from content-job start, not from browser navigation or total elapsed time. Zero latency and 100% accuracy are not guaranteed.

Speech actions select an existing unambiguous speech tab or open a new speech tab in the extension's browser profile when only chat is open. Multiple speech tabs require one unambiguous active speech tab. This does not establish that the extension is installed in a different browser or profile, and does not refresh an existing draft automatically.
2. Parse all dialogue turns in original order. Keep a persistent cast ledger: character, independently auditioned voice, perceived presentation, baseline style and per-turn direction. Do not infer gender from a voice name; verify it. Distinct characters require distinct voices unless the user explicitly requests reuse. Do not alternate speakers by index.
3. The user's chosen batching rule is maximal consecutive turns with at most two characters. A third character starts a new batch. The observed editor may alternate block assignment and the second voice selection can fail. The planner's conceptual batches are not proof the adapter can execute them; verify every text, speaker, voice and style before running. Never substitute a shared voice silently.
4. Run once and keep the job ID. For timeout, 403, unknown state or missing output inspect the same job and page; do not automatically resend, change billing, or reset a queue. Guarded `recover_page` refreshes only a verified empty landing page. A draft, audio or uncertain state must be preserved. A welcome/terms dialog is not evidence of a successful generation.

For an explicitly authorized generation, local bridge action `setup_and_run` accepts the same `turns` payload as `setup_screenplay`. It verifies setup and invokes Run once in the same job, avoiding a second enqueue/poll round trip. Its completed result reports `setupToRunClickMs`; this measures only the interval between completed setup verification and the Run click, not end-to-end latency or generation time. It does not download; immediately issue download and verify the WAV before the next batch. Failure after dispatch can mean Run happened: inspect the same job and page, never blindly repeat. Existing audio, unverified casting or setup failure must block Run. This action is not the disabled `generate_screenplay` all-in-one download pipeline and may not be exposed by the MCP wrapper.

Live check 2026-11-19: one short Fola test returned setupToRunClickMs=6 and setupMs=2476; Run completed and a 3.0-second, 24 kHz mono WAV was downloaded. One measurement is not a latency guarantee, nor a two-speaker or long-script benchmark; audio performance was not auditioned.
5. After each batch, download promptly and verify the actual file and playable duration, and where possible listen and compare with the script. `get_audio` can expose a short sample or a different player; never accept a tiny preview or an unassociated file as the batch. Browser download initiation alone is not completion. Save each take under a unique project name and record batch order, cast, styles, source and result.
6. Join completed contiguous batches in original order; avoid forced alignment when no internal cut is needed. If splitting an existing long recording, independent ASR and human listening must verify boundaries; forced alignment can place words across the next line and is not proof of speech. Check transitions and loudness, preserve source WAVs, and disclose unverified pronunciation or acting.
7. Be quick by retaining a verified cast, batching consecutive compatible turns, avoiding unnecessary navigation/alignment, and preparing the next batch while verification proceeds only where operations do not race. Never sacrifice the checks above or promise a fixed speedup without measurements. A continuous automatic pipeline is not currently verified: the all-in-one action is disabled, the old runner uses unsupported commands, and second-speaker voice selection remains unresolved. A 403 previously occurred; its cause was not established. Report blockers honestly and never claim a final file before it is produced and reviewed.

Past artifacts `vastu-final.wav` and `vastu-full-voice-draft.wav` are drafts with unverified acting and inconsistent/shared casting, not approved final masters. The user requested work on this runbook and fixes before providing a new script; do not start new audio generation unless asked.

## Run timing and HTTP errors — user preference

After verified setup, wait one second and invoke Run once. Recheck editor readiness and existing output at Run time; do not add a second blind Run if the outcome is uncertain. setupToRunClickMs includes the intentional one-second pause. Page load and Google generation time are separate.

For a Google AI Studio HTTP 404 or 5xx error: inspect the same job and page first. If generation may have started, or a draft/output might exist, preserve and download any output and establish the outcome before retrying. Once failure is confirmed and any content is saved, return to the verified speech landing page, create a fresh dialog, restore the exact script, voice and style, then run once. Inspect account, model, connection and service status if the failure recurs; do not loop or blindly refresh. An HTTP 404 from the local bridge can instead mean an incorrect route or missing job; inspect that separately and do not assume Google generation failed. Never change billing or accept terms automatically.
