## Speech editor
Each region named “Speech block” contains speaker button, Style, + Expression, block preview, Speech to text and editable “Speech block text”. Add speech block appends another block. In an existing sample with multiple blocks, each additionally had Delete speech block; the sample had two speakers, independently styled lines and an audio player with play, seek and download. Do not assume controls or maximum speaker count are identical for all models.

Style opens a menu with free-form “Describe the voice style” (tone, mood, pace) and presets: Whisper (whisper quietly), Friendly (warm and neutral delivery with micro-pauses), Narration (commanding, rich vocal modulation, dramatic pauses), Promote (high energy, elongated vowels), Podcast (calm, measured delivery). Per-block styles in sample differed even for the same speaker. Free-form style input and sample descriptions observed; actual generation results have not been tested.

Expression opens an Expression tags toolbar. Observed choices: argh, breath, cackle, cheer, chuckle, chuckles, cough, cry, exhales, gasp, giggle, groan, growl, grr, grunt, heavy breath, hiss, laugh, laughter, long pause, moan, pant, pff, phew, scream, short pause, shout, shriek, sigh, sighs, sneeze, snicker, snort, sob, throat-clearing, tsk, whimper, whispering, whispers, yawn. The text field suggests typing '<' for tags; sample text uses e.g. <gasp> and <short pause>. Insertion location and model-specific tag compliance remain untested.

Speaker button opens Speaker settings panel: current voice and sample playback, search ('Search 2,000+ voices'), New voice, Language, Gender, Pitch, Style and Use case filters, categorized voice lists; voice rows include selection, favorite, remix, sample controls. Speaker settings on right also opens this panel. Voice names and categories are dynamic; do not hardcode as exhaustive. New voice generation, filters, second speaker creation and selection persistence remain untested.

## Agent workflow
1. Confirm URL and open Create new dialog; confirm Speech block exists.
2. Analyze script into ordered blocks and a consistent speaker assignment. Pick voices based on required language, delivery and sample; avoid assuming voice availability.
3. Write per-block style directions for tone, pacing, intensity and delivery; insert expression tags sparingly at intended positions. Preserve user text unless instructed to edit.
4. Discover current TTS-capable models from UI or documented supported API, record model ID, capabilities and source timestamp; present unknown pricing/access as unknown. Verify selection before generation.
5. Enter blocks, validate actual values and speaker/style associations; then generate only under the user's authorized cost and quota constraints. Inspect result and errors before download.
6. For extension implementation, use scoped accessible roles/names and block containers; reacquire elements after page transitions, handle async rendering, ambiguity and localization. Do not use accessibility snapshot indexes or fixed coordinates as durable selectors. Confirm any DOM selectors against actual DOM; no DOM was inspected in this session.

## Backup-first workflow
Before every Run/regeneration or model change that might replace the current player, download current completed result, wait for browser download to finish, verify the file exists and nonzero, copy or save it into the designated test/project folder under a unique versioned name, then verify metadata. Only then generate again. The browser player exposed a single current output in these observations; durable history and automatic deletion semantics were not independently proven. The manually downloaded WAVs are 24 kHz mono 16-bit PCM and can be imported into an audio/video editor. Retain script, model, speaker, style, expression, timestamp and filename in a manifest for repeatability.

Legacy 3.1 Preview generation completed and was downloaded as test-audio/04-dialogue-3.1-preview.wav. UI auto-selected Zephyr and Puck when switching; the 3.8 per-block custom style was not visible in the legacy composer, so it must not be assumed preserved. The resulting WAV was verified separately with ffprobe.
