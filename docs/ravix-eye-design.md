# RAVIX Flow observation architecture and speech extension design

Inspection 2026-11-13 of local RAVIX extension backup, not a claim about all versions: R:\Ranjan Vishwakarma\29 oct 2026\RAVIX\extension_backup_godlevel. Manifest v3 has side panel, content scripts, service worker, storage, downloads, scripting and local bridge permissions. flow_super_sync.js builds a visible DOM matrix using labels, roles, bounding rectangles and observed UI state; assigns semantic target IDs, watches DOM changes with a debounced MutationObserver and periodically publishes state. flow-agent-background.js polls a localhost bridge and routes actions/results. flow-god-eye-network.js observes selected network status signals. The inspected state report is DOM-derived, not evidence of actual screenshot-based vision. It uses layout/label heuristics and can misidentify elements after redesign; freshness and confidence matter.

Proposed speech-specific equivalent (not implemented): content script emits compact structured state for landing/editor/model dialog/voice dialog, block order, speaker IDs, style, expressions, model, generation status, current output and backup status. Action dispatcher uses semantic IDs, validates unique match and pre/postconditions, rejects stale snapshots, waits for state transitions and reports explicit errors. Observe mutations, debounce and publish only changed fields; avoid streaming private prompt text by default. Optional screenshot capture only on user request, with browser permissions and clear privacy boundaries. A local authenticated bridge can expose versioned snapshots/actions to approved agents; avoid unauthenticated remote access, arbitrary JS execution, and hidden sensitive data collection. Model and voice discovery must be dynamic, capability-checked, timestamped and graceful when a paid key or restricted catalog is encountered. Backup gate must prevent a new generation before previous output has been saved and verified unless the user explicitly chooses otherwise. Downloads need unique filenames, verified completion, recovery and a project manifest; do not depend solely on one in-page player. Cross-browser permissions, content script lifecycle, tab selection and download behavior require real browser tests.

Not yet verified: exact AI Studio DOM selectors or shadow roots, every dialog, audio quality, full catalog, multiple browser support, extension/bridge implementation, and full recovery. This is an architecture proposal informed by the observed backup, not a tested integration.
