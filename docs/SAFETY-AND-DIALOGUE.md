A 0.04-second preview was also mistaken for generated audio. A transcript-forced timestamp is not proof that a word was spoken or a cut is correct.

Before generation, build a cast table with a distinct, stable voice per character. Specify each character's intended voice presentation and audition the selected voice in the actual language; select an appropriate feminine voice for a female character when the brief calls for it and an appropriate masculine voice for a male character. Do not assume a voice's presentation from its name; mark it unverified until auditioned. If a character's presentation is unspecified, do not invent it. Reuse a voice across characters only with an explicit creative decision. Assign a baseline vocal identity plus concise turn-specific performance direction; verify every speaker and style in the editor.

When separate dialogue takes are requested, one verified take per turn provides boundaries directly and often avoids full-length forced alignment. Arrange files in original script order using measured sample durations, retain source WAVs and make a manifest. If a two-speaker batch is used, keep consecutive turns in story order and verify the complete batch before proceeding. Long grouped-by-character recordings need independent ASR and verified boundaries before reordering. Do not use forced alignment as an accuracy test: compare independent ASR with actual spoken audio and review word cuts. Never trim to timestamps blindly when adjacent boundaries overlap. ASR, VAD, pauses and silence are aids, not proof of exact words. Target a faster method through fewer full-length passes and cached models, but do not promise 10% time or equivalent quality without measured benchmarks and listening checks.

User preference for the current story: use maximal contiguous batches with at most two distinct characters, even when they alternate many times. On a third distinct character, save and verify the current batch before proceeding. Concatenate verified complete batches in the original order; this does not require word-level forced alignment. If the actual editor cannot assign a required speaker (including consecutive turns by the same person), report the limitation and use smaller execution batches only when authorized; never silently claim the requested batch was generated. ## Refresh and recovery

For an editor-opening or voice-catalog failure during setup, the extension checks the page before attempting recovery. It refreshes once and retries setup only when it can verify the speech landing page has no text, audio or active generation. It waits for the tab's completed navigation event and a fresh speech-page scan; a failed or uncertain recovery is reported and must be inspected. The local bridge action `recover_page` performs the same guarded refresh without submitting a generation. If the editor has text, a custom voice/style, audio, a running job, or an unknown page state, preserve it and report the blocker instead of resetting it. Save and verify any existing audio before opening a new dialog. Never automatically repeat Run, download, or a dispatched command whose outcome is unknown, and do not reset or clear the queue to hide a timeout or a 403. Inspect the original job and page, then resolve the actual access or UI problem. Refresh can resolve stale page state but is not a guarantee that a missing control or 403 will disappear. This check does not repair the known second-speaker voice selection failure.

An AI Studio "Welcome to AI Studio" dialog may contain a Continue button that accepts terms. Scan reports `welcome_terms` when it recognizes the dialog, blocks Run, and instructs the agent to inspect it. Only after the user explicitly authorizes that specific Continue action, the local bridge `continue_welcome` may click a uniquely recognized Continue in that dialog and verify dismissal. Do not treat this as blanket consent to changed or future terms; do not click unrelated dialogs or keep refreshing a blocking modal.

`setup_screenplay` accepts `turns: [{speaker, voice, text, style}]`. Each turn needs an explicit style and each character an explicit voice. The current adapter supports at most two named characters per batch; for more, use ordered batches or separate turns, preserve voice names, verify the output and assemble in order. The current Google editor appears to assign new blocks alternately; its speaker chip opens voice settings, not a verified speaker-switching menu. If the existing block assignment does not match the requested character sequence (including consecutive turns by the same character), setup stops before entering text. Use separate ordered batches in that case. Setup requires a fresh dialog and rejects conflicting voices, unrecognized models, missing controls, excess blocks and existing text/audio. A failure can leave added blocks or partial edits: inspect before retrying. A successful setup checks text, speaker labels, styles and selected voice; the output must still be auditioned.

`run` requires a verified speech editor and no existing output; it clicks once, requires an observed Stop indicator and then an enabled download control. If a start or completion times out, the result is unknown; inspect the same job and page before any retry. Download reports only an initiation, not a verified file. Save and verify the file and its content before generating another take. `generate_screenplay` is intentionally disabled until download association can be proven; use the separate steps. Do not claim a successful output from a successful setup alone.

The older bridge/run_project.py describes `prepare_turn` and `run_turn`, which the currently installed content handler does not implement. Do not use that runner or claim its end-to-end operation until it is repaired and tested. Model capabilities and UI can change; stop on unrecognized state instead of guessing. This guide and mock tests do not establish acoustic accuracy, account availability, quota or real generation reliability.
